# 深度代码审查 Prompt

> 从最小审查（min）到最大审查（max）的分级模板。根据变更范围选择对应级别。

## 审查级别

| 级别 | 适用场景 | 维度数 | 预计耗时 |
|------|----------|--------|----------|
| **Min** | 单文件小修复 | 3 | 5 min |
| **Standard** | 功能迭代（≤5 文件） | 6 | 15 min |
| **Max** | 发版前全量审查 | 10 | 30+ min |

---

## Min 审查（3 维度）

```
请对以下变更执行 3 维度审查：

1. **正确性**：逻辑是否正确？边界条件是否覆盖？
2. **防御性**：null/空/NaN/越界是否有守卫？
3. **一致性**：与现有代码风格、命名、架构是否一致？

输出格式：
- P0（必须修复）：会导致崩溃/数据错误
- P1（建议修复）：潜在风险
- P2（改善）：可读性/性能优化
```

---

## Standard 审查（6 维度）

```
请对以下变更执行 6 维度并行审查：

1. **正确性**：算法逻辑、边界条件、数值精度
2. **防御性**：null/NaN/Inf/空集合/越界守卫完整性
3. **安全性**：注入、路径穿越、信息泄漏、资源耗尽
4. **一致性**：架构分层、命名规范、文档同步
5. **性能**：O(N²) 退化、不必要分配、缓存缺失
6. **测试覆盖**：新增代码是否有对应测试？边界是否覆盖？

输出格式：
- 按 P0→P3 分级
- 每项包含：文件:行号 | 问题描述 | 修复建议
- 最后给出总结：通过/有条件通过/需返工
```

---

## Max 审查（10 维度）

```
请对本项目执行发版前全量深度审查，覆盖以下 10 个维度：

1. **算法正确性**：数值算法与 Python 参考实现一致；边界条件覆盖
2. **防御编程**：NaN/Inf/null 守卫；异常过滤器；无裸 catch
3. **安全**：路径沙箱；SQL 参数化；正则超时；无敏感信息泄漏
4. **架构合规**：UDF→Core→Foundation 单向；无跨层调用
5. **文档一致性**：api-reference 签名与代码一致；函数计数准确
6. **测试完备性**：CrossVal 无自校验；边界/退化输入覆盖
7. **性能**：无 O(N²) 退化；热路径无不必要分配
8. **错误处理**：哨兵契约一致；WrapError 不兜底
9. **兼容性**：双 TFM (net48+net8.0) 均通过；Excel-DNA 封送兼容
10. **工程规范**：无死代码；命名一致；commit 粒度合理

输出格式：
[P{级别}] {文件}:{行号} — {问题} → {修复建议}
统计 + 结论：🟢/🟡/🔴
```

## 审查前置条件

- [ ] 已加载 agents.md（了解红线和架构）
- [ ] 已加载对应 skills/（了解语言陷阱）
- [ ] 已运行 `dotnet test`（确认当前基线）

## 审查后行动

| 发现级别 | 行动 |
|----------|------|
| P0 | 立即修复，不可跳过 |
| P1 | 本次修复，除非有明确豁免理由 |
| P2 | 记录到改进计划，下次迭代处理 |
| P3 | 可选修复，不阻塞发版 |
