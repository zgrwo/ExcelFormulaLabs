# ADR 模板 — 架构决策记录

> 重大架构决策必须记录：新增/移除架构层、引入框架、改变依赖方向、迁移技术栈。
> 文件位置与编号规则：
> - 存放于 `rules/adr/`，文件名 `NNNN-简短描述.md`（编号 4 位递增，如 `0001-dual-tfm.md`）
> - 编号全局唯一，不因决策被撤销而重用
> - 决策被推翻时：保留原 ADR，更新其「状态」为 `已废弃`，并在新 ADR 的「上下文」中引用

## 复制以下模板

```markdown
# ADR-NNNN: {决策标题}

**日期**: {YYYY-MM-DD}
**状态**: {草稿 | 已确认 | 已废弃}

## 上下文
{问题背景：为什么需要这个决策？当前约束是什么？
  若替代/废弃旧决策，引用对应 ADR 编号。}

## 决策

{具体决策内容：做了什么选择？边界在哪里？}

## 原因

1. {理由 1（可验证的好处）}
2. {理由 2}
3. {理由 3}

## 约束

- {强制性约束 1（如：某层禁止 import 某框架）}
- {约束 2}

## 影响

- {正面影响 1}
- {负面影响/代价 1}
- {需要同步更新的文档/代码位置}

## 演进

- **{YYYY-MM-DD}**: {修订记录（何时被修改/废弃，引用后续 ADR）}
```

## 何时必须写 ADR

| 场景 | 示例 | 必须 |
|------|------|:----:|
| 引入/移除架构层 | 新增 Engine 层 | ✅ |
| 引入新框架/依赖 | 引入 ORM / 事件总线 | ✅ |
| 改变依赖方向 | 底层开始引用上层 | ✅ |
| 技术栈迁移 | xlwings → Web UI | ✅ |
| 内部实现重构 | 算法重写（无 API 变化） | ❌ 记 CHANGELOG 即可 |

## 审查检查项

- [ ] 编号唯一且递增
- [ ] 「约束」可被代码结构验证（CI 或 grep 可检查）
